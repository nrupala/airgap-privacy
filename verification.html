The product

AirGap Keyboard (package org.aimlds.airgap) is an Android-only keyboard. “Air-gapped” means two things, and both hold: your data never leaves your phone — the app has no INTERNET permission, so Android blocks every connection it could try to open — and no other app on your phone can read what the keyboard keeps: its learned words, clipboard and scheduled messages sit in the app's own private storage, sealed as AES-256-GCM ciphertext with the key held in your phone's Android Keystore, and the app opens no door into that storage. Android backup is off for this app.

Test evidence for this release

  • Core test battery: 5,214 checks, all passing — the keyboard's core logic, including the auto-send verdict logic and the dictionary preservation rules, exercised on the exact tree this release was built from.
  • Emoji data battery: 17,063 checks, all passing — every emoji sequence the keyboard ships, verified against its source data.
  • Artifact security probes: 8 of 8 passing — run against the built APK itself: permission surface is exactly Microphone + Google Play Billing with no INTERNET permission; internal components are not exposed to other apps; backup is off; the build is not debuggable; no key material inside the package.
  • Independent gate: PASS, no findings. Under this house's rules the person who builds a release never grades it. A separate tester checked out the release tree fresh, re-ran the full battery, verified the artifact fingerprints above, and swept the auto-send verdict logic across its full 96-case truth table — it reports SENT in exactly one case: the one where the send is positively confirmed.

Software bill of materials

The release's SBOM (CycloneDX 1.5, 17 components) is published here: sbom-v2.6.7.cdx.json. One known vulnerability is on record, stated plainly: Guava 32.1.2-android, carried inside the Google Play Billing library, is subject to CVE-2026-102554 (GHSA-xxph-c9ww-hj94), a deserialization memory-exhaustion flaw. The keyboard's own code never uses Guava and contains no Java deserialization path, so the flaw is unreachable in this app; it is recorded as an accepted risk in the project's bench report, and that acceptance lapses the moment the billing library changes.

Scope of this page

Every number above belongs to version 2.6.7 (44) and the artifacts named here. A later version gets its own updated page before it is called verified. What no page can prove is your phone itself — the app's own Proof screen (Settings → About → Proof) runs the permission, network-refusal and encryption checks live on your device, with your phone's own key.
